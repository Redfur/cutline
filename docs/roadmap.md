# План

Пять этапов. Каждый заканчивается состоянием, в котором инструментом можно пользоваться — ни один не оставляет проект в нерабочем виде.

---

## Этап 1. Модель и рендерер

Внешне не меняется ничего, но макет перестаёт быть прошитым в коде.

- [x] Каркас проекта: Vite, React, TypeScript
- [x] Типы модели документа из `docs/document-model.md`
- [x] `render(doc, record, opts) → SVG` — чистая функция без обращений к DOM
- [x] Измерение текста: единый модуль для превью и экспорта
- [x] Автоподгонка: режимы `shrink`, `clip`, `wrap`
- [x] Макет бейджа из прототипа, описанный документом, а не кодом
- [x] Экспорт SVG и PNG
- [x] Сохранение и загрузка проекта файлом

**Готово, когда** текущий бейдж собирается из JSON и экспортируется так же, как в прототипе.

## Этап 3. Данные

- [x] Таблица записей: добавление, удаление, редактирование ячеек
- [x] Колонки: создание, переименование, удаление
- [x] Импорт CSV с сопоставлением колонок
- [x] Экспорт CSV
- [x] Подстановка плейсхолдеров в текст и в изображения
- [x] Сетка миниатюр: все записи разом
- [x] Подсветка проблем: переполнение, пустое обязательное поле
- [x] Переключение предпросмотра между записями

Замечено по ходу, не сделано:

- Картинка на запись — только ссылкой в ячейке. Загрузку файла в ячейку **не делаем**:
  в таблице данных только текст (решение пользователя)
- [x] Рамка текста не совпадала с текстом: «по центру» — ошибка рендера (центрировалась
      нулевая высота блока), «по базовой линии» — `y` был самой базовой линией. Теперь
      базовая линия последней строки на нижнем крае рамки; документ v2, миграция v1→v2
- [x] Витрина UI-кита (`UiKitDemo`) убрана из `App.tsx`. `Tooltip`, `Badge`, `Switch` из
      `src/ui/` пока без применения — остаются частью порта дизайн-системы
- [x] Инструмент (текст/фигура/изображение) не создаёт элемент поверх другого: клик ловит
      оверлей элемента под курсором, даже заблокированного. На бейдже карточку целиком
      накрывает «Рамка карточки» — добавить элемент кликом по ней нельзя. Заодно: клик —
      размер по умолчанию, протягивание — сразу нужный размер (Shift, Esc, привязки);
      линия — в любом направлении, с маркерами на концах
- [x] Перетаскивание и ресайз оставляли float-шум («47.37500000000001» в инспекторе) —
      дельта драга округляется до 0.1 мм (`roundMouseMm`), итог чистится от двоичного хвоста
- [x] Первый кадр холста до `ResizeObserver`: карточка на мгновение не по центру —
      размер вьюпорта меряется в `useLayoutEffect`

- [x] Инспектор приведён к макету дизайн-системы: секции и шапка, типографика в pt/%,
      выравнивание иконками, цвета документа рядом с каждым полем цвета, замок и поле
      поворота в «Положении и размере» (резайз повёрнутого элемента), галочки видимости
      обреза/вылета/безопасного поля, сводка переполнений у холста. Из макета **не
      перенесено**: встроенные OFL-шрифты (Golos Text, Manrope, PT Serif, JetBrains Mono) с
      четырьмя начертаниями — нужны миграция `weight` и вшивание в экспорт, логично вместе
      с кривыми на Этапе 4; прозрачность цвета — нет в модели; привязка к сетке 0,5 мм;
      секция «Данные» (файл таблицы, «Заменить таблицу») в инспекторе холста

**Готово, когда** двадцать пять карточек видно одним экраном и понятно, где что сломалось.

## Этап 4. Печать

- [x] PDF через pdf-lib: вылеты, TrimBox и BleedBox
- [x] Перевод текста в кривые
- [x] Метки реза
- [x] Спуск полос: несколько карточек на лист, выбор формата листа
- [x] Вариант с полями для домашнего принтера
- [ ] Двусторонняя печать: зеркальный оборот — **отложено** (решение пользователя): у модели
      нет оборота. Отдельный шаг: вторая сторона в документе (миграция v3), переключатель
      «Лицо | Оборот» на холсте, в PDF — лист оборота с зеркальной раскладкой
- [x] Пакетный экспорт: все записи одним PDF

Сделано по ходу и замечено:

- [x] Встроенные OFL-шрифты: Golos Text, Manrope, PT Serif, JetBrains Mono, Regular и Bold
      (`src/fonts/`). Только они попадают в PDF; системный шрифт — понятная ошибка с именем
      слоя, растровый текст не делаем. В инспекторе встроенные — сверху, системные помечены
      «не для PDF»
- PDF собирается из SVG `render()` (кривые + вылет), а не отдельным обходом документа
- [x] В шапке одна кнопка «Экспорт» и меню «…» (новый / открыть / сохранить) — по макету
      `Chrome.jsx`, вместо отдельных кнопок под каждый формат. Экспорт — диалог «Экспорт
      тиража» по `ExportDialog` из дизайн-системы (не выезжающая панель из ui-spec — её в
      макете нет): формат PDF/PNG/SVG, раскладка, записи (все / текущая / диапазон), метки и
      вылет, плашки проблем записей и системного шрифта. PNG/SVG нескольких записей — ZIP
- [x] Спуск (`src/export/imposition.ts`): ячейки встык, вылеты соседей касаются, поворот на
      90°, если так влезает больше; метки по общим линиям реза снаружи блока. A6 на A4: 4 встык,
      2 с вылетом и метками; «для домашнего принтера» — поля 5 мм, 4 на листе при 95%.
      Карточка на листе обрезается по своему viewBox — вылезший элемент не заезжает на соседнюю
- Метки убраны из `render()`: рисовались за viewBox и не были видны; это свойство листа
- Не сделано из ui-spec: предпросмотр первой страницы в диалоге, разрешение PNG (300 dpi
  зашито), пункты меню из макета без функциональности («Дублировать документ», «Печать
  пробного листа», «Горячие клавиши», «Удалить документ»), имя документа в шапке (Этап 5)
- Кривые совпадают с измерением canvas до тысячной мм во всех восьми начертаниях. Ловушка:
  Chromium шейпит текст по словам и пары с пробелом не кернит, opentype.js — кернит; у
  PT Serif такие пары есть, строка в кривых выходила уже на 0,7 мм. Кривые строятся по словам
- Не сделано: четыре начертания из макета (нужна миграция `weight`), пользовательские шрифты
  (`source: "user"`), CMYK (цвета в PDF — RGB, как в модели), текст в PDF живым текстом
  вместо кривых (переключатель в ui-spec)

**Готово, когда** файл можно отправить в типографию без правок.

## Инфраструктура (не привязано к этапам, начинать по готовности)

- [x] Локальное сохранение: документ и вид (режим, текущая запись) — в IndexedDB через
      `idb-keyval`, автосохранение через 500 мс, скелетон редактора на время загрузки,
      кнопка «Новый». История undo между перезагрузками не сохраняется. Несколько
      вкладок — последняя запись выигрывает (не решено). Список недавних документов —
      вместе со стартовым экраном, Этап 5.
- [x] Автоматические тесты: Vitest, среда node. Покрыта чистая логика: `snap.ts`,
      `resizeElement.ts`, `fit.ts`, `measure.ts` (через фейковый 2D-контекст), переходы
      истории `history.ts`; с Этапа 3 — `layout.ts` (переполнение), `data/placeholders`,
      `data/problems`, `data/csv`, `editor/lib/records.ts`. **Не покрыто**: окно коалесцинга и `boundary` в
      `useDocumentHistory` (завязано на время и React — нужен jsdom + testing-library или
      вынос решения в чистую функцию с инжектируемым временем), компоненты и холст
      (проверяются Playwright-сценарием, см. CLAUDE.md).
- [ ] CI: GitHub Actions на push/PR — build + lint + test (когда тесты появятся).
- [x] Рефакторинг компонентов `src/editor/`: по папкам, `Canvas.tsx` разбит на `Ruler`,
      `GuideLine`, `ElementOverlay` и хуки драга, инлайн-стили → CSS-модули. Поведение не
      менялось — сверено попиксельно со скриншотами до рефакторинга. `src/ui/` сознательно
      не трогали: это порт дизайн-системы, держим его близко к исходнику в Claude Design.
