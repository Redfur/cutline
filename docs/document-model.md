# Модель документа

Документ — обычный JSON. Он целиком описывает макет и данные, сохраняется файлом и передаётся в рендерер.

## Верхний уровень

```ts
interface Document {
  version: number;            // для миграций при изменении схемы
  name: string;               // имя в шапке и списке документов; едет с файлом
  canvas: Canvas;
  fonts: FontRef[];
  elements: Element[];
  records: Record<string, string>[];
  fields: FieldDef[];         // описания колонок данных
  guides: Guide[];            // пользовательские направляющие (линейка), см. ниже
}

interface Canvas {
  w: number;                  // мм, размер в обрезе
  h: number;
  bleed: number;              // мм, вылет под подрезку
  safe: number;               // мм, поле, за которое не стоит заходить
  background: string;         // цвет или "transparent"
}
```

## Элементы

Общая часть у всех типов:

```ts
interface Base {
  id: string;
  name: string;               // отображается в списке слоёв
  type: "text" | "rect" | "ellipse" | "line" | "image";
  x: number; y: number;       // мм, левый верхний угол относительно обреза
  w: number; h: number;
  rotation: number;           // градусы
  locked: boolean;
  visible: boolean;
}
```

### Текст

```ts
interface TextElement extends Base {
  type: "text";
  content: string;            // "Имя" или "{{name}}" или "ID: {{badgeId}}"
  font: string;               // семейство из fonts
  weight: 400 | 500 | 600 | 700;   // как CSS font-weight
  size: number;               // мм по кеглю
  minSize: number;            // нижняя граница при автоподгонке
  lineHeight: number;
  tracking: number;           // межбуквенный интервал, мм
  align: "left" | "center" | "right";
  valign: "top" | "middle" | "baseline";
  color: string;
  fit: "shrink" | "clip" | "wrap" | "none";
  transform: "none" | "upper" | "lower";
}
```

`valign` — где текст стоит по вертикали внутри рамки `y..y+h`; во всех режимах рамка охватывает текст:

- `top` — верх первой строки (ascent шрифта) на верхнем крае
- `middle` — по центру весь блок, от ascent первой строки до descent последней
- `baseline` — базовая линия последней строки на нижнем крае (`y + h`); свисающие элементы букв уходят ниже. Тексты разных кеглей с одним `y + h` стоят на одной базовой линии

`fit` — ключевое свойство, ради которого проект затевался:

- `shrink` — уменьшать кегль до `minSize`, потом обрезать многоточием
- `clip` — сразу обрезать многоточием
- `wrap` — переносить по словам в пределах `h`
- `none` — выпускать за границы как есть

### Фигуры

```ts
interface RectElement extends Base {
  type: "rect";
  fill: string | null;
  stroke: string | null;
  strokeWidth: number;        // мм
  radius: number;             // мм
}
```

`ellipse` и `line` устроены так же, у линии вместо заливки только обводка.

У линии `x, y` — начало, `x + w, y + h` — конец: `w/h` — вектор, **может быть отрицательным** (линия «вверх-вправо» — `h < 0`). У остальных типов `w, h ≥ 0`. Коробку элемента (хитбокс, подсветка на линейках) редактор берёт через `boundsOf` (`src/editor/lib/geometry.ts`), а не из `w/h` напрямую. Старые документы с линиями `h: 0, w > 0` остаются валидными.

### Изображение

```ts
interface ImageElement extends Base {
  type: "image";
  src: string;                // data URI или "{{photo}}"
  fit: "cover" | "contain" | "fill";
}
```

## Направляющие

```ts
interface Guide {
  id: string;
  axis: "x" | "y";
  positionMm: number;
}
```

Тянутся с линейки на холст (как в Фигме) — дополнительные цели примагничивания сверх обреза/вылета/безопасного поля/других элементов. Не печатаются и не попадают в `render()` — это редакторская сущность, но живёт в документе, а не в состоянии редактора: так она проходит через undo/redo и сохраняется вместе с макетом.

## Данные

```ts
interface FieldDef {
  key: string;                // "name", подставляется как {{name}}
  label: string;              // "Имя" — заголовок колонки в таблице
  sample: string;             // пример для предпросмотра пустого макета
}
```

`records` — массив плоских объектов. Ключи соответствуют `fields[].key`.

## Плейсхолдеры

В `content` и `src` подставляются значения записи по шаблону `{{key}}`. Одна строка может содержать несколько: `"{{city}}, {{country}}"`. Неизвестный ключ подставляется пустой строкой, а не текстом плейсхолдера.

Ключ — любые символы, кроме фигурных скобок; пробелы по краям внутри скобок игнорируются (`{{ name }}` = `{{name}}`). Кириллица допустима: колонка CSV «ФИО» становится полем `{{ФИО}}`. Разбор шаблона — один на проект, `src/data/placeholders.ts`.

Пока записей нет, редактор показывает карточку на записи из `fields[].sample`.

Смена ключа поля в редакторе переписывает и ключ во всех записях, и `{{old}}` → `{{new}}` в `content`/`src` элементов. Удаление поля убирает ключ из записей, плейсхолдер в макете остаётся — инспектор показывает его как «нет поля».

## Проблемы записи

Считаются в `src/data/problems.ts` той же раскладкой текста (`layoutText` в `src/render/layout.ts`), что рисует `render()`, — «подсвечено» и «обрезано в файле» не могут разойтись.

- **Переполнение** текстового элемента: `shrink` — не влезло даже на `minSize`; `clip` — пришлось обрезать; `wrap` — строк больше, чем вмещает `h`, или слово шире `w`; `none` — шире `w`. Помечаются все поля, использованные в этом элементе.
- **Пусто** — пустое (после trim) значение поля, которое использует видимый текст или изображение. Важнее переполнения, если оба сразу.

Скрытые элементы не проверяются: на печать они не попадают.

## CSV

`src/data/csv.ts`. Экспорт: разделитель `;`, UTF-8 с BOM, заголовки — `label` полей (открывается в русском Excel без мастера импорта). Импорт: RFC 4180, разделитель `;`/`,`/табуляция определяется по первой строке, кодировка UTF-8 или Windows-1251 (выбирается сама, если UTF-8 даёт `U+FFFD`). Колонки сопоставляются с полями по `label` или `key` без учёта регистра, остальные по умолчанию становятся новыми полями с ключом из заголовка. Пустые строки пропускаются. Импорт заменяет записи или добавляет к ним — одним шагом истории.

## Версии и миграции

`version` — версия схемы, сейчас **4**. Документ старой версии приводится к текущей в `src/model/migrate.ts`, который вызывается из `validateDocument` — одинаково при открытии файла и при загрузке сессии из IndexedDB, так что редактор и `render()` видят только текущую схему. Документ новее редактора не открывается с понятной ошибкой.

- **v1 → v2**: `valign: "baseline"` раньше значил «`y` — базовая линия первой строки» (текст над `y`, рамка под ним). Миграция делает `y −= h` — однострочный текст остаётся на месте; многострочный поднимается на `(n−1)·lineHeight`.
- **v2 → v3**: у документа появилось `name` (шапка, список документов, имя файла при сохранении). Старые документы получают «Без названия». v3 с пустым или испорченным именем открывается с тем же «Без названия» (`validateDocument`).
- **v3 → v4**: вес шрифта — число, как CSS `font-weight`, чтобы завести Medium и SemiBold. `"regular"` → 400, `"bold"` → 700 у текстов и в `fonts`. Тип входа миграции — `AnyVersionDocument` (вес строкой или числом): так фикстура бейджа в v1 и старые файлы проходят шаги без приведений.

## Хранение

Кроме файла («Сохранить в файл» / «Открыть файл…») документы автоматически сохраняются в IndexedDB браузера (`src/storage/documents.ts`, библиотека `idb-keyval`): база `cutline`, store `documents`, ключи с префиксами (второй object store idb-keyval без апгрейда базы не открывает):

```ts
// doc:<id> — документ целиком
interface StoredDocument {
  id: string;                 // UUID, не переиспользуется
  doc: CutlineDocument;
  view: { mode: "design" | "data"; recordIndex: number; borders: {...} };
  savedAt: number;            // Date.now()
}
// index — список для переключателя без чтения тяжёлых документов, свежие сверху
type Index = { id: string; name: string; savedAt: number }[];
// last — id последнего открытого документа
```

Документ и строка индекса пишутся одной транзакцией с явным `commit()`. `last` пишет не сохранение, а `Workspace` при открытии документа (`rememberOpened`): документ, на который переключились без правок, не сохраняется, а отложенное сохранение закрытого редактора дописывается позже открытия следующего и возвращало бы `last` на закрытый. Документ кладётся объектом (структурное клонирование), не JSON-строкой. При загрузке `doc` проходит тот же `validateDocument`, что и файл; битая запись в списке — «не открывается» с кнопкой «Убрать», редактор не падает. Не сохраняются: история undo, зум, выделение.

Старая одиночная сессия (ключ `current`, до Этапа 5) при первом чтении списка становится документом — одной readwrite-транзакцией вместе с проверкой «индекса ещё нет», чтобы два одновременных чтения (StrictMode, вторая вкладка) не перенесли её дважды. Запись в удалённый за эту сессию документ отбрасывается: иначе отложенный flush автосохранения его воскрешал бы.

## Шрифты

```ts
interface FontRef {
  family: string;
  weight: 400 | 500 | 600 | 700;   // как CSS font-weight
  source: "bundled" | "user";
  file?: string;              // путь или data URI для user
}
```

Встроенные шрифты — только с открытой лицензией. Пользовательские живут в памяти сессии и сохраняются в проект как data URI, чтобы файл открывался на другой машине.

Сейчас встроены четыре семейства: **Golos Text, Manrope, JetBrains Mono** — по четыре начертания (Regular 400, Medium 500, SemiBold 600, Bold 700), **PT Serif** — два (Regular, Bold); `src/fonts/files/` c лицензиями OFL, каталог в `src/fonts/bundled.ts`. Golos, Manrope и JetBrains Mono в google/fonts вариативные, opentype.js оси не инстанцирует — в репозитории лежат статичные срезы wght=400/500/600/700 (`fontTools varLib.instancer --update-name-table`; у JetBrains Mono в STAT нет значения 600, имена SemiBold выставлены руками).

Веса, которого у семейства нет (PT Serif 500/600), файла тоже нет: `resolveWeight` подбирает начертание по правилу CSS (500 → 400, 600 → 700). `FontFace` регистрируется с настоящим весом файла, поэтому браузер выбирает тот же файл, из которого строятся кривые. Инспектор показывает только начертания семейства и при смене семейства сразу ставит подобранный вес.

`TextElement.font` — по-прежнему имя семейства строкой. Встроенное семейство распознаётся по имени: на экране редактор регистрирует его `FontFace` из того же файла (лениво, только используемые документом), в PDF текст идёт кривыми из этого файла. Системный шрифт (Arial и т.п.) остаётся для экрана и SVG, но PDF с ним не собирается — понятная ошибка с именем слоя, а не растровый текст. Пользовательские шрифты (`source: "user"`) пока не сделаны.

## Что рендерер делает с документом

```ts
function render(
  doc: Document,
  record: Record<string, string>,
  opts: { outlines: OutlineFonts | null; bleed: boolean }
): string   // строка с SVG
```

Единственная точка, где документ превращается в картинку. Из неё же растут PNG (через canvas) и PDF (через pdf-lib).

`outlines` — разобранные шрифты для перевода текста в кривые (`(family, weight) → opentype.Font | undefined`, `src/render/outline.ts`) или `null`. Шрифты приходят аргументом: рендерер файлы не грузит. Текст, для шрифта которого кривых нет, остаётся `<text>`. Раскладка строк та же (`layoutText`), кривые повторяют только отрисовку строки.

**PDF** (`src/export/`) строится из SVG `render()` с кривыми и вылетом, а не вторым обходом документа: `svgToPdfOps.ts` разбирает закрытое подмножество тегов, которое пишет `render()` (незнакомый тег — ошибка, не пропуск), `pdf.ts` рисует команды pdf-lib в мм SVG через одну матрицу на страницу. Страницы — листы спуска полос (`imposition.ts`): одна карточка на странице (страница = обрез + вылет + зона меток; TrimBox — обрез, BleedBox — обрез + вылет) или несколько на A4/A3/SRA3 (ячейки встык; если так влезает больше, лист становится альбомным — карточки не поворачиваются; поля 5 мм для домашнего принтера, по желанию — с уменьшением, чтобы уместить столько же). Вылет и метки — независимые настройки. Карточка ставится на лист матрицей и обрезается по своему viewBox. Метки реза — свойство листа, их строит спуск, в `render()` их нет. Цвета — RGB как в модели.
