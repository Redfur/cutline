# Инструкции для работы над проектом

Этот файл читается автоматически в начале каждой сессии. Здесь то, что нельзя вывести из кода.

Отвечай пользователю на русском языке.

Если по ходу работы что-то здесь устарело — сменился стек, команда, архитектурное решение, — обнови этот файл тем же изменением, а не оставляй расхождение на потом.

## Что это за проект

Конструктор печатных карточек с переменными данными. Подробности — в `README.md`, схема документа — в `docs/document-model.md`, план — в `docs/roadmap.md`, раскладка экранов — в `docs/ui-spec.md`.

Работаем по этапам из роадмапа последовательно. Не начинай следующий, пока текущий не закончен и не проверен вручную в браузере.

## Команды

- `npm install` — установка зависимостей
- `npm run dev` — dev-сервер (Vite)
- `npm run build` — проверка типов (`tsc -b`) и продакшен-сборка
- `npm run lint` — Biome, линт и проверка форматирования
- `npm run format` — Biome, форматирование с записью
- `npm run preview` — локальный просмотр собранного `dist/`
- `npm test` — Vitest (`vitest run`), среда node без jsdom

CI и деплой — `.github/workflows/ci.yml`: на push/PR — lint, test, build; на push в `main` — публикация `dist/` на GitHub Pages (https://redfur.github.io/cutline/). Сайт живёт в подкаталоге, поэтому `base` передаётся при сборке (`npm run build -- --base=/cutline/`), а в `vite.config.ts` не прописан. Ресурсы подключать через импорт (`?url`, как шрифты в `fonts/bundled.ts`) — абсолютный путь `"/…"` на Pages даст 404. Проверить сборку из подкаталога локально: `npm run build -- --base=/cutline/ && npx vite preview --base=/cutline/`.

Линтер и форматтер — только Biome (`biome.json`), ESLint/Prettier не добавляем. `reference/` из проверки Biome исключён: это замороженный прототип, его не переписываем.

## Дизайн-система и мокапы

Дизайн-система живёт в Claude Design, проект **Cutline Design System** (`projectId` `7ee489d8-7b16-4f32-adec-fbaac1f7571b`) — токены (цвета, типографика, spacing), React-компоненты (`Button`, `TextField`, `LayerRow` и т.д.) и полный набор мокапов редактора: режимы **Дизайн** и **Данные**, обязательные состояния (ничего не выделено / выделен элемент / переполнение текста), диалог экспорта, импорт CSV.

**`/design-sync` тут не подходит** — этот скилл синхронизирует в обратную сторону: локальную библиотеку компонентов *в* Claude Design, а не мокапы *из* него. У нас наоборот: дизайн-система уже готова в Claude Design, а в репозитории своей нет. Токены и переиспользуемые компоненты (`components/core`, `forms`, `feedback`, `overlays`, `editor` — не `ui_kits/`) читаются вручную через `DesignSync`(`get_file`/`list_files`, read-only, без запроса прав) и переносятся в `src/ui/` как строгий TypeScript — .jsx→.tsx, `.d.ts` сливается в тот же файл интерфейсом `<Name>Props` (отдельных `.d.ts` в проекте нет, см. `src/model/document.ts`).

**Экраны приложения — в отдельном проекте cutline** (`projectId` `53851476-3643-4f67-ae2e-40fa4bfe908f`): `Cutline Editor.dc.html` со всеми состояниями (`design`, `empty`, `overflow`, `data`, `data-empty`, `data-problems`, `data-import`, `data-import-errors`, `export`, `start` — `CL_STATES`), код — `editor/CutlineEditor.jsx`; там же `Cutline Documents.dc.html` и `editor/data.js` — данные макета, в том числе шаблоны стартового экрана (`CL_DATA.templates`; перенесены в `src/templates/templates.ts` с переводом единиц: кегль pt → мм, межстрочный % → множитель, трекинг % кегля → мм, вес — как есть, первый слой макета — верхний). Это главный макет экранов: экран собирать по нему, а из дизайн-системы брать компоненты и токены. В `DesignSync list_projects` этого проекта нет (список показывает только дизайн-системы) — читать `list_files`/`get_file` прямо по `projectId`. Файл большой: `get_file` сохраняет его на диск, нужный компонент искать `grep`-ом. `ui_kits/editor/*` дизайн-системы — более ранние наброски тех же экранов; если они расходятся с проектом cutline или с `docs/ui-spec.md` — **спросить пользователя**, а не выбирать самому (так экспорт сначала сделали модальным диалогом по `ui_kits`, хотя в проекте cutline и в ui-spec это сайдбар).

`ui_kits/editor/*` (Chrome/Canvas/Inspector/DataView/DataImport) — не переносить как код: это собранные макеты экранов на фейковых данных, а не переиспользуемые части. Смотреть их через `DesignSync` как референс при реализации конкретной задачи, а сам экран собирать из `src/ui/` компонентов и настоящей модели документа.

## Архитектурные правила

**Рендерер не знает про редактор.** Функция `render(document, record) → string` в `src/render/` не обращается к DOM, не читает состояние редактора и не зависит от React. Всё, что ей нужно, приходит аргументами. Это не стилистическое предпочтение: на этой функции держатся превью, сетка миниатюр и все виды экспорта.

**Геометрия в миллиметрах.** Координаты, размеры, кегли, отступы — миллиметры в модели документа. Перевод в пиксели происходит только в компоненте холста, в одном месте. Никаких магических множителей по коду.

**Схема документа меняется только с миграцией.** Поле `version` + шаг в `src/model/migrate.ts` (зовётся из `validateDocument`, значит, одинаково для файла и для сессии из IndexedDB) + тест. Редактор и `render()` видят только текущую схему. Фикстура бейджа держит координаты прототипа в v1 и приводится той же миграцией.

**Модель документа — единственный источник правды.** Редактор меняет документ, интерфейс отражает документ. Не храни позиции элементов в состоянии компонентов.

**Undo/redo с первого дня.** Любое изменение документа проходит через единый слой истории. Прикрутить это позже — переписать половину проекта.

**Данные — чистые функции в `src/data/`** (`placeholders.ts`, `functions.ts`, `problems.ts`, `csv.ts`), без DOM и React, с тестами рядом. Функции в плейсхолдерах (`{{ pad(n(), 3) }}`) разбирает только `placeholders.ts` — подстановка, ключи из аргументов, переименование колонки и обязательные поля идут через его дерево выражения, второго разбора не заводим; новая встроенная функция — запись в `FUNCTIONS` (`functions.ts`) + тест. Функции чистые и без сети — их зовёт синхронный `render()`. Номер записи для `n()` — обязательный параметр (`RenderOptions.n`, `Scope`): у холста — текущая запись + 1, у экспорта — `card.index + 1`. Переполнение считается через `layoutText` (`src/render/layout.ts`) — ту же раскладку, которой пользуется `renderText`; второй копии измерений текста не заводим. Правки записей/полей как документ → документ — в `src/editor/lib/records.ts`, UI только оборачивает их в `history.set`. Текущая запись предпросмотра — состояние `EditorShell` (как зум), не документ; она же выделенная строка таблицы.

**Картинки в `render()`.** QR (`{{ qr(…) }}` — весь `src`) рисуется вектором, путями из абсолютных `M/L/C/Z` (`render/qr.ts`), оформление — `ImageElement.qr`. Формой рисуются только модули данных (`types` из `uqr`), служебные узоры — квадратами: иначе код не читается. Новая форма — проверь декодером со скриншота (`jsqr` через `npm install --no-save`), а не на глаз. Заглушку пустой и не загрузившейся картинки рисует `render()` только с `preview` (редактор); экспорт передаёт `preview: null`. Какие ссылки сломаны, проверяет `editor/lib/useBrokenImages.ts` и передаёт набором — `render()` в сеть не ходит.

**PDF — из SVG `render()`, текст — кривыми встроенного шрифта.** `src/export/pdf.ts` не обходит документ заново: `svgToPdfOps.ts` разбирает то подмножество SVG, которое пишет `render()` (новый тег в `render()` = новый case там, незнакомый тег — ошибка). pdf-lib системных шрифтов не видит, поэтому в PDF попадает только текст встроенным шрифтом (`src/fonts/bundled.ts`, OFL, 400–700; у PT Serif только 400/700 — недостающий вес подбирает `resolveWeight` по правилу CSS, и экран, и кривые берут один файл), переведённый в кривые (`render/outline.ts`, шрифты приходят в `render()` аргументом `outlines`); системный — ошибка до сборки (`pdfPreflight.ts`). На экране встроенный шрифт — `FontFace` из того же файла (`fonts/load.ts`), поэтому canvas и кривые меряют одно. Кривые строятся по словам: Chromium не кернит пары с пробелом. pdf-lib и opentype.js грузятся лениво (`import()` в `TopBar` и `pdfExport.ts`, разбор шрифтов — `fonts/outlineFonts.ts`, не `load.ts`) — в основной бандл их не тянем. В тестах шрифты — `fonts/testFonts.ts` (`import.meta.glob` + `?inline`, без `fs` и типов node в `src/`); pdf-lib работает в node — PDF проверяется тестом целиком, с повторным чтением. Метки реза и раскладка на лист — в `export/imposition.ts` (чистые функции), не в `render()`: метки — свойство листа, а не карточки. Карточка на листе обрезается по своему viewBox.

**Экспорт — одна кнопка «Экспорт» в шапке и сайдбар справа** (`src/editor/ExportPanel/`, по `ExportPanel` из проекта cutline, состояние `export`), файловые действия — в меню «…». Новые форматы и настройки добавляются в панель, отдельных кнопок в шапке не заводим. Решения панели без JSX (какие карточки, подписи, счётчики, сводка проблем) — `editor/lib/exportChoice.ts`; сборка — `export/batch.ts`, тяжёлое (pdf-lib, opentype.js, fflate) грузится `import()` по требованию. Превью первого листа — `export/sheetPreview.ts` из того же `pageLayout` и настоящего `render()`. Спуск поворачивает лист, а не карточки; вылет и метки — раздельные настройки. Пока панель открыта, горячие клавиши редактора выключены (`EditorShell`).

**Сохранение — в IndexedDB, не в localStorage** (`src/storage/`): картинки в документе — data URI, лимит localStorage (~5 МБ) кончается на первой фотографии. Доступ — через `idb-keyval`, свою обёртку над `IDBRequest` не пишем. Документов несколько (`storage/documents.ts`: `doc:<id>`, `index`, `last` — см. docs/document-model.md, «Хранение»). **Маршруты — в hash** (`wouter`, только `useHashLocation`; разбор — чистый `editor/lib/routes.ts`): `#/new` — стартовый экран, `#/doc/<id>` — «Дизайн», `#/doc/<id>/data` — «Данные», `#/` и незнакомое — последний открытый. Hash, а не path: у GitHub Pages нет SPA-fallback. Режим — проп `EditorShell` из адреса, не его состояние: «Назад» возвращает и режим. Ушли с документа — `Workspace` забывает его снимок (`opened`): версия на момент открытия, смонтированная заново, затёрла бы правки; документ, с которого ушли на старт, и только что созданный берутся из памяти (`memory`), остальные — из IndexedDB. `Workspace` по адресу решает, какой документ открыт, и делает всё со списком (переключить, создать, открыть файл новым документом, дублировать, удалить) и пишет `last` при открытии (`rememberOpened`, не сохранение — см. document-model.md). «Новый документ» из открытого — стартовый экран с возвратом к документу: `EditorShell` отдаёт текущие `doc` и вид, а не снимок на момент открытия; сам документ правит `EditorShell` с `key={id}` — у каждого документа свой редактор и своя история undo. `Workspace` читает документ **до** монтирования `EditorShell` — иначе автосохранение успеет записать пустой лист поверх сохранённого; пока ждём дольше 150 мс — `EditorSkeleton`. Имя документа — поле модели (v3), переименование идёт через `history.set`. Планировщик (`storage/autosave.ts`) — чистый, с тестами; `useAutosave` только проводка. Запись коммитится явно (`transaction.commit()`) — без этого правка прямо перед F5 терялась: транзакция ждёт возврата в цикл событий, а страница уже выгружается. Всё, что меняет документ, автоматически сохраняется — отдельно звать сохранение не нужно.

**Справка — панель справа поверх экрана** (`src/editor/HelpPanel/`, по `HelpPanel` из проекта cutline, состояние `help`): не модальная, без затемнения, 340 px под шапкой, поверх инспектора — так в макете, решение пользователя. Состояние — в `Workspace` (над стартом и редактором, при смене документа не закрывается), остальным — контекст `useHelp()` (`editor/lib/help.ts`: `open(topic?)`, `toggle`, `close`, `setHidden`). F1 — везде; Esc закрывает, если он не нужен диалогу, меню или полю ввода вне справки (слушатель в capture — на старте Esc иначе ещё и «Вернуться»). Пока открыт экспорт, справка скрыта (`setHidden`). Раскрыт раздел текущего экрана; `open(topic)` раскрывает раздел пункта, прокручивает и подсвечивает его. Текст — данные в `src/help/content.ts` (у пункта `id`), поиск — чистый `src/help/search.ts`, раздел функций собирается из `FUNCTIONS` (`title`/`description`/`example`). **Новая функция, клавиша или настройка — пункт в справке тем же изменением**; писать по коду, а не по макету (его текст устарел: обещает V/T/⌘O/⌘P и двустороннюю печать).

**Создание элемента инструментом** (`src/editor/Canvas/useDrawElement.ts`, фабрики — `src/editor/lib/createElement.ts`): клик — размер по умолчанию с центром в точке (`placeElement`), протягивание дальше 3 px — рамка от точки нажатия (`drawElement`), Shift — квадрат/45°, Esc — отмена. Инструмент «QR-код» — не свой тип элемента, а картинка с `qr()` в `src` (`PlaceType`, `createQr`), всегда квадратная (`alwaysSquare`). Пока выбран инструмент размещения, оверлеи и направляющие получают `interactive={false}` и пропускают мышь — иначе нельзя начать элемент поверх другого (даже заблокированного).

**У линии `w/h` — вектор от начала к концу и может быть отрицательным**, у остальных типов `w, h ≥ 0`. Всё, что показывает «коробку» элемента (хитбокс, подсветка на линейках, рамка черновика), берёт её через `boundsOf` (`src/editor/lib/geometry.ts`), а не из `w/h` напрямую. У линии два маркера на концах (`moveLineEnd`), хитбокс — сама линия (прозрачная обводка), а не коробка: у диагонали коробка накрывала бы соседей.

**Привязки и направляющие** (`src/editor/lib/snap.ts`, `src/editor/Canvas/` — драг в `useElementDrag.ts`/`useGuideDrag.ts`) — к другим элементам, центру, обрезу/вылету/безопасному полю, и к пользовательским направляющим (тянутся с линейки, тип `Guide` в `src/model/document.ts`, живут в документе — undo/redo и сохранение работают сами по себе, не отдельный слой состояния). Резайз и перемещение примагничиваются по-разному (`snapMove` — три точки на ось у всего бокса, `snapResize` — только двигающийся край), общие приватные хелперы `axisTargets`/`bestSnap` в одном файле, не дублируются. Видимость обреза/вылета/безопасного поля (галочки «Направляющие» в инспекторе холста) — состояние вида (`ViewState.borders`, сохраняется в сессии), не документ; скрытая граница не рисуется и не примагничивает. У повёрнутого элемента резайз идёт через `resizeRotated` (противоположный маркер стоит на месте) и без привязки — края не параллельны осям.

**Инспектор собран по `ui_kits/editor/Inspector.jsx`**: шапка (`InspectorHeader`) + секции `PanelSection` с заголовками, общая «Положение и размер» с замком (`GeometrySection`), плашки переполнения (`OverflowAlert`) сверху. Заблокированный элемент — остальные секции в `LockedFieldset` (нативный `disabled`, не протаскиваем проп в каждое поле). Кегль показывается в pt, межстрочный и трекинг — в % (трекинг — % от кегля); модель остаётся в мм/множителе, перевод только в `src/editor/lib/units.ts`. Быстрые цвета у каждого `ColorField` — цвета документа (`lib/documentColors.ts`), не фиксированная палитра.

## Стиль кода

- TypeScript строгий, `any` не используем
- Функциональные компоненты, хуки
- Раскладка компонентов и стили `src/editor/` — по разделу «Структура `src/editor/`» ниже, для каждого нового компонента
- Комментарии объясняют **почему**, а не **что**. Комментарий вида `// увеличиваем счётчик` не нужен; комментарий `// кегль уменьшаем до 60% — ниже начинает конфликтовать с соседней колонкой` нужен
- Комментарии и сообщения коммитов на русском, идентификаторы и имена файлов на английском
- Не создавай файлы, пока они не нужны. Пустые заглушки «на будущее» не добавляй
- **Числовые поля** — `TextField` из `src/ui/forms/` уже различает числовой режим по `typeof value === "number"` (отдельный проп не нужен): стрелки вверх/вниз меняют значение на 1 (10 с Shift, 0.1 с Alt — подтягивая к ближайшей границе сетки шага, а не просто прибавляя), минус и промежуточный ввод («-», «4.») не перетираются контролируемым value на лету. Новые числовые поля — переиспользуй этот компонент, не изобретай свою обработку `onChange`/клавиш заново

## Структура `src/editor/`

Подобие FSD: слайсы с публичным API, без слоёв `app/widgets/features/entities`.

```
src/editor/
  <Component>/                 компонент верхнего уровня (Canvas, Inspector, LayersPanel, …)
    index.ts                   публичный API: сам компонент и его типы (Props и т.п.)
    <Component>.tsx
    <Component>.module.css     только если у компонента есть стили
    useSomething.ts, constants.ts   сопутствующее, нужное только этому компоненту
    <SubComponent>/            подкомпонент, нужный только родителю, — та же структура
  lib/                         логика без JSX, общая для компонентов, + *.test.ts рядом
```

Имя компонента не должно совпадать с глобалом браузера/JS — Biome (`noShadowRestrictedNames`) не пропустит: режим «Данные» поэтому `DataMode`, а не `DataView` (это типизированные массивы), по той же причине модель — `CutlineDocument`, а не `Document`.

**Новый компонент создаём так — всегда, даже если он в десять строк:**

1. Папка `<Name>/` в PascalCase, по имени компонента. Если компонент нужен только одному родителю, папка лежит внутри родителя (`Canvas/Ruler/`, `Inspector/TextInspector/`, `LayersPanel/GuideRow/`). Если нужен нескольким, она лежит рядом с ними на ближайшем общем уровне (`Inspector/PositionSizeFields/` — общий для инспекторов по типам).
2. `<Name>.tsx` — `export function <Name>` и `export interface <Name>Props`. Второй компонент в тот же файл не кладём, даже маленький: он получает свою папку (так вынесены `GuideRow` и `CanvasInspector`).
3. `index.ts` — только реэкспорт: `export { <Name> } from "./<Name>";` и `export type { <Name>Props, … } from "./<Name>";`. Логики в нём нет.
4. `<Name>.module.css` — если есть стили. Пустой не заводим, стили одного компонента в модуль другого не кладём. Правила стилей ниже.
5. Хуки и константы, нужные только этому компоненту, лежат в его папке (`Canvas/useElementDrag.ts`, `Canvas/constants.ts`). Логику без JSX, нужную нескольким компонентам или покрываемую тестами, выносим в `lib/`.

**Импорты.**
- Снаружи папки импортируем только её `index.ts`: `../Canvas`, `./Ruler`, но не `../Canvas/Canvas` и не `./Ruler/Ruler`.
- Внутри папки соседние файлы подключаем напрямую (`./constants`, `./Canvas.module.css`), а не через свой же `index.ts`, иначе будут циклы.
- `lib/` — набор независимых модулей без общего `index.ts`, импортируем конкретный файл: `../lib/snap`, `../../lib/resizeElement`.

**Стили.**
- CSS-модули. Инлайн `style` — только для значений, вычисленных из документа и зума: координаты и размеры в px, `rotate`.
- Ось или состояние задаём классом-модификатором (`.x`/`.y`, `.selected`, `.interactive`), а не условием в `style`.
- Размеры, которые уже есть в токенах, берём токеном (`var(--ruler-size)`, `var(--row-h)`), а не числом.

**`lib/`** — чистые функции (`snap.ts`, `resizeElement.ts`, `history.ts`, `createElement.ts`, `records.ts`, `plural.ts`, `units.ts`, `documentColors.ts`) и хуки без JSX: `useDocumentHistory.ts` (стоит на `history.ts`), `useFontsVersion.ts`, `useAutosave.ts` (стоит на `storage/autosave.ts`). Тесты лежат рядом (`snap.test.ts`). React-компонентов тут нет.

`src/ui/` под эти правила не подпадает: это порт дизайн-системы, он остаётся плоским, на инлайн-стилях и `useHover`, как в исходнике Claude Design.

## Проверка перед тем, как считать задачу сделанной

- `npm test` проходит (Vitest)
- `npm run build` проходит без ошибок и предупреждений TypeScript
- `npm run lint` проходит без ошибок (Biome — линт и форматирование)
- Изменение проверено в браузере — по-настоящему, не только «код выглядит правильно» (см. «Как проверять в браузере» ниже)
- Экспортированный SVG открывается и совпадает с тем, что на экране
- Если трогал геометрию — проверь на карточке с очень длинным и очень коротким текстом

Новый функционал сопровождается тестами с первого коммита, не отдельным шагом потом. Тесты — `*.test.ts` рядом с модулем, `vitest` импортируется явно (без глобалов). Логику, которую хочется протестировать, выносим из хука/компонента в чистую функцию (как `lib/history.ts` из `lib/useDocumentHistory.ts`), а не тащим jsdom. То, что завязано на DOM и мышь (холст, драг, вёрстка), проверяется Playwright-сценарием по разделу ниже.

## Как проверять в браузере

Расширение Claude in Chrome есть не в каждой сессии (например, в фоновых — оно требует
живого подключённого браузера). Рабочий способ, который не зависит от этого, — headless
Playwright, гоняется через `npx`/временную установку, в зависимости проекта не входит:

```
npm run dev &                      # поднять dev-сервер
npx playwright screenshot --viewport-size=1100,1700 --wait-for-timeout=800 \
  http://localhost:5173 /путь/к/скриншоту.png
```

Если браузер ещё не скачан, `npx playwright screenshot` сам подскажет запустить
`npx playwright install chromium` (~180 МБ, один раз, дальше берётся из кеша). Файл
скриншота смотреть через Read — это реальный Chromium, не догадка по коду.

Так на этом же макете уже нашёлся реальный баг: `<svg>` из `render()` рендерился в
своём intrinsic mm-размере и вылезал под соседнюю карточку — не видно было в коде,
только на скриншоте.

**Для интерактивной проверки (клики, драг, клавиатура) одного скриншота мало** — нужен
реальный сценарий мышью/клавиатурой, а не только «код выглядит правильно». Рабочий цикл:

1. `npm install --no-save playwright` (не остаётся в `package.json`, ставится и сносится
   на время проверки)
2. Написать одноразовый скрипт `.scratch-<название>.mjs` в корне репозитория (не внутри
   `src/`, чтобы точно не попал в сборку/линт) — `chromium.launch()`, реальные
   `page.mouse.move/down/move/up`, `page.keyboard.press`, читать состояние через
   `getBoundingClientRect()`/значения полей, а не полагаться на то, что «должно было
   получиться»
3. `node .scratch-<название>.mjs`, смотреть вывод/ассерты
4. Убрать `.scratch-*.mjs`, `npm uninstall --no-save playwright`, поднять dev-сервер
   заново для следующей сессии, если нужно

Этим способом в этой же сессии ловились реальные баги, которые не видны по коду: клик
без движения мыши по направляющей неотличим от «отпустили над линейкой» и удалял её;
эффект с `mousemove`/`mouseup` подписывался на устаревшее значение из замыкания вместо
свежего аргумента апдейтера; перепутанная ось при перетаскивании с линейки.

**Для рефакторинга без изменения поведения** — снять эталон до правок и сравнивать попиксельно
после каждого шага: тот же скрипт сохраняет скриншоты ключевых состояний (пусто, выделение,
середина драга со снапом, направляющая, переполнение текста, бейдж) + итоговые значения полей
инспектора + экспортированный SVG, а одноразовый `.scratch-diff.mjs` сравнивает папки через
`pixelmatch`/`pngjs` (`npm install --no-save`). Прогон дважды на одном коде должен дать 0
отличий — иначе сценарий недетерминирован и сравнение ничего не доказывает.

**Справка в сценариях** — `aside[aria-label="Справка"]`, раскрытый раздел — `[data-topic] > section` с содержимым, пункт — `[data-topic="<id>"]`. Панель перекрывает инспектор: чтобы кликнуть в нём, сначала закрой её (F1).

**Адреса в сценариях.** Документ открывается прямо по `http://localhost:5173/#/doc/<id>` (`/data` — «Данные»), id берётся из `new URL(page.url()).hash`; `page.goBack()` проверяет «Назад». Кнопка «…» — `getByRole("button", { name: "Меню", exact: true })`: в «Данных» есть «Меню поля …».

**IndexedDB в сценариях.** Состояние теперь переживает `page.reload()` и живёт в профиле контекста — для чистого старта бери новый `browser.newContext()`. Медленный или сломанный IndexedDB подменяется через `context.addInitScript` на `IDBFactory.prototype.open` (задержка — чтобы увидеть скелетон; `throw` — режим «хранилище недоступно»). Документ подкладывается прямо в IndexedDB из страницы: `import("/node_modules/idb-keyval/dist/index.js")` + `createStore("cutline", "documents")`. Шапка: кнопка имени — `button[aria-haspopup="listbox"]`, переключатель — `[role="listbox"][aria-label="Документы"]`, текущий документ в нём всегда первой строкой — выбирать строку по имени, а не по номеру. Перед `reload` после правки жди конца дебаунса («Сохранено» висит и до правки — сначала `waitForTimeout(700)`), иначе сработает вопрос `beforeunload`.

**Подводные камни локаторов.** Переключатель «Дизайн | Данные» — `role="radio"`, не `button`. SVG карточки на холсте — `svg[viewBox="0 0 105 148"]`, а не первый `svg` на странице (это иконка). `outerHTML` SVG из DOM не равен строке `render()` побайтно (`<rect …></rect>` вместо `<rect …/>`) — сравнивай содержимое, а не байты. Кнопка «Экспорт» в шапке — `getByRole("button", { name: "Экспорт", exact: true })`, иначе совпадёт с «Экспортировать N карточек»; «Открыть файл…» в меню «…» даёт событие `filechooser` (input скрыт). Панель экспорта — `section[aria-label="Экспорт"]`, переключатели в ней — `role="radio"` (как «Дизайн | Данные»), селекты — нативные `<select>`.

**Субпиксельный шум измерений.** `getBoundingClientRect()`/`boundingBox()` в этом
окружении дают шум порядка 0.1–0.3мм (иногда до ~1px) — сама карточка холста
перецентровывается при росте контента, поэтому кэшировать её координаты один раз в
начале скрипта нельзя, брать свежими перед каждым действием. Если ассерт с точным
номинальным значением падает на пару десятых мм — это почти наверняка шум измерения,
а не баг: сравнивай с реально измеренным состоянием (прочитать текущую позицию элемента/
направляющей из DOM), а не с тем, что «должно было получиться» по арифметике, и давай
допуск ~0.2–0.3мм на такие сравнения.

## Коммиты

Крупную фичу делим на несколько осмысленных коммитов, а не на один большой diff — каждый коммит должен быть самодостаточным шагом, а не случайной точкой остановки.

После того как работа закончена и проверка выше пройдена — коммить. Но не `git push`: пуш только по отдельной явной просьбе.

**Работаем прямо в `main`.** Никаких отдельных веток и git worktree под задачу, в том числе в фоновых сессиях — правки и коммиты сразу в основном checkout на `main`. Разделение на шаги — через осмысленные коммиты, не через ветки. Защиту фоновых сессий, которая требует worktree перед правками, отключает `.claude/settings.json` (`"worktree": {"bgIsolation": "none"}`) — не убирать.

## Известные подводные камни

**Текст — самая трудоёмкая часть.** Переносы, автоподгонка по кеглю, выравнивание по базовой линии съедают больше времени, чем весь остальной редактор. Закладывай это в оценки.

**Измерение текста.** В прототипе ширина строки считается через canvas `measureText` для системных шрифтов и через метрики opentype.js для загруженных. Превью и экспорт обязаны использовать один и тот же способ измерения, иначе вёрстка разъедется между экраном и печатью.

**Загрузка веб-шрифтов.** Canvas `measureText` меряет тем шрифтом, что загружен сейчас: пока шрифт документа догружается, текст меряется запасным (он уже), и длинное имя «влезает». Всё, что мемоизировано по документу и зависит от измерения (проблемы, миниатюры), берёт в зависимости `useFontsVersion()` — иначе первая подсветка проблем остаётся посчитанной по запасному шрифту. Реальный баг Этапа 3: холст рисовал запись обрезанной, а сетка её не обводила.

**Кернинг кривых и экрана.** Canvas/SVG `<text>` в Chromium шейпит по словам — пары с пробелом не кернятся, opentype.js кернит всю строку. Отсюда `outline.ts` раскладывает строку по словам. Новый встроенный шрифт — проверь ширину canvas против `outlineWidth` в браузере (расхождение должно быть < 0,01 мм).

**Файлы .ttc не парсятся** opentype.js. Menlo и Monaco на macOS лежат именно в коллекциях — нужна понятная ошибка с объяснением, а не молчаливый сбой.

**Печать без полей.** Четыре карточки A6 закрывают A4 целиком, места под поля не остаётся. Домашние принтеры срезают 3–5 мм с каждого края. Спуск полос должен это учитывать и предлагать вариант с уменьшением.
