# Инструкции для работы над проектом

Этот файл читается автоматически в начале каждой сессии. Здесь то, что нельзя вывести из кода.

Отвечай пользователю на русском языке.

Если по ходу работы что-то здесь устарело — сменился стек, команда, архитектурное решение, — обнови этот файл тем же изменением, а не оставляй расхождение на потом.

## Что это за проект

Конструктор печатных карточек с переменными данными. Подробности — в `README.md`, схема документа — в `docs/document-model.md`, план — в `docs/roadmap.md`, раскладка экранов — в `docs/ui-spec.md`.

Работаем по этапам из роадмапа последовательно. Не начинай следующий, пока текущий не закончен и не проверен вручную в браузере.

## Команды

- `npm install` — установка зависимостей
- `npm run dev` — dev-сервер (Vite)
- `npm run build` — проверка типов (`tsc -b`) и продакшен-сборка
- `npm run lint` — Biome, линт и проверка форматирования
- `npm run format` — Biome, форматирование с записью
- `npm run preview` — локальный просмотр собранного `dist/`

Линтер и форматтер — только Biome (`biome.json`), ESLint/Prettier не добавляем. `reference/` из проверки Biome исключён: это замороженный прототип, его не переписываем.

## Дизайн-система и мокапы

Дизайн-система проекта живёт в Claude Design, проект **Cutline Design System** (не в этом репозитории). Там — токены (цвета, типографика, spacing), React-компоненты (`Button`, `TextField`, `LayerRow` и т.д.) и полный набор мокапов редактора: режимы **Дизайн** и **Данные**, обязательные состояния (ничего не выделено / выделен элемент / переполнение текста), диалог экспорта, импорт CSV.

Начиная с Этапа 2 (редактирование) интерфейс собирается по этим мокапам, а не придумывается заново — раскладка, отступы, цвета, копирайтинг там уже решены. Компоненты и токены затягиваются в репозиторий через `/design-sync`, инкрементально, по мере того как они нужны текущему этапу — не всё сразу.

## Архитектурные правила

**Рендерер не знает про редактор.** Функция `render(document, record) → string` в `src/render/` не обращается к DOM, не читает состояние редактора и не зависит от React. Всё, что ей нужно, приходит аргументами. Это не стилистическое предпочтение: на этой функции держатся превью, сетка миниатюр и все виды экспорта.

**Геометрия в миллиметрах.** Координаты, размеры, кегли, отступы — миллиметры в модели документа. Перевод в пиксели происходит только в компоненте холста, в одном месте. Никаких магических множителей по коду.

**Модель документа — единственный источник правды.** Редактор меняет документ, интерфейс отражает документ. Не храни позиции элементов в состоянии компонентов.

**Undo/redo с первого дня.** Любое изменение документа проходит через единый слой истории. Прикрутить это позже — переписать половину проекта.

## Стиль кода

- TypeScript строгий, `any` не используем
- Функциональные компоненты, хуки
- Комментарии объясняют **почему**, а не **что**. Комментарий вида `// увеличиваем счётчик` не нужен; комментарий `// кегль уменьшаем до 60% — ниже начинает конфликтовать с соседней колонкой` нужен
- Комментарии и сообщения коммитов на русском, идентификаторы и имена файлов на английском
- Не создавай файлы, пока они не нужны. Пустые заглушки «на будущее» не добавляй

## Проверка перед тем, как считать задачу сделанной

- `npm run build` проходит без ошибок и предупреждений TypeScript
- `npm run lint` проходит без ошибок (Biome — линт и форматирование)
- Изменение проверено в браузере вручную, а не только «код выглядит правильно»
- Экспортированный SVG открывается и совпадает с тем, что на экране
- Если трогал геометрию — проверь на карточке с очень длинным и очень коротким текстом

## Коммиты

Крупную фичу делим на несколько осмысленных коммитов, а не на один большой diff — каждый коммит должен быть самодостаточным шагом, а не случайной точкой остановки.

После того как работа закончена и проверка выше пройдена — коммить. Но не `git push`: пуш только по отдельной явной просьбе.

## Чего не делаем в первой версии

Группы и слои-папки, кривые Безье, тени и эффекты, совместное редактирование, аккаунты, облачное хранение, версионирование документов, мобильное редактирование.

Каждый пункт выглядит как небольшая добавка и каждый стоит недели. Если возникает соблазн — предложи, но не начинай без подтверждения.

## Известные подводные камни

**Текст — самая трудоёмкая часть.** Переносы, автоподгонка по кеглю, выравнивание по базовой линии съедают больше времени, чем весь остальной редактор. Закладывай это в оценки.

**Измерение текста.** В прототипе ширина строки считается через canvas `measureText` для системных шрифтов и через метрики opentype.js для загруженных. Превью и экспорт обязаны использовать один и тот же способ измерения, иначе вёрстка разъедется между экраном и печатью.

**Файлы .ttc не парсятся** opentype.js. Menlo и Monaco на macOS лежат именно в коллекциях — нужна понятная ошибка с объяснением, а не молчаливый сбой.

**Печать без полей.** Четыре карточки A6 закрывают A4 целиком, места под поля не остаётся. Домашние принтеры срезают 3–5 мм с каждого края. Спуск полос должен это учитывать и предлагать вариант с уменьшением.

**Привязки и выравнивание.** Без них двигать элементы мышью мучительно. Сделать хорошо — неожиданно сложно. Отдельная задача, не «заодно».
